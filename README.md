# ikura

名画を白・灰・黒の3値のマス目で写して、明暗（バリュー）を見る目を鍛えるPWA。朝、布団の中でiPadかスマホを使い、1日数分で終わる練習にする。

毎日1枚、パブリックドメインの名画が出る。その横の16×12の粗いマス目を3色で塗って写し、答え合わせで、お手本を3値に分けた正解との一致率を見る。鍛えたいのは、明るさを見分けて大きな形にまとめる目で、バリュースタディと同じ練習になる。

## 使い方

GitHub Pagesで配信する。iPadではSafariで開いてホーム画面に追加し、全画面で使う。AndroidではChromeで開く。

## 仕様

### 作品は先に用意して、リポジトリから配る

作品はアプリから美術館のAPIを呼んで取らない。`scripts/` のスクリプトで、Art Institute of ChicagoとMetropolitan Museum of Artのパブリックドメインの絵画を数百枚取ってきて、`artworks/` に入れておく。サーバーを持たず、GitHub Pagesだけで動かすためである。Metropolitan Museumの画像はCORSのヘッダーを返さないので、ブラウザから直接読むとcanvasが汚染されてピクセルを読めない。

スクリプトは作品ごとに次のことをする。

- 絵画でないもの（版画・写真・工芸など）と、縦横比が4:3から離れすぎたものを外す。
- 4:3（横長）か3:4（縦長）に中央で切り抜き、長辺800pxのJPEGに縮める。
- 3値の正解を作る。マスごとの平均の明るさを出し、マス全体の明るさの分布を三等分して境目にする。明るさの固定値で切ると、暗い絵が全部黒になるためである。
- 3値に分けても明暗の幅が狭いもの（ほぼ真っ黒な絵など）を外す。
- 並び順を一度シャッフルして、`artworks/index.json` に書く。

`artworks/index.json` には、作品ごとに画像のファイル名、タイトル、作者、所蔵館、元のページのURL、向き、3値の正解を持つ。正解はスクリプトで作っておくので、アプリでは画像のピクセルを読まない。

### 1日1枚、日付で進める

決まった基準日からの日数を作品の数で割った余りで、今日の1枚を選ぶ。一巡するまで同じ絵は出ず、iPadとAndroidで同じ日に同じ絵が出る。

練習に向かない絵が出たときは「別の絵」のボタンで並びの次の絵に替える。替えたことはその日のうちだけ `localStorage` に残し、開き直しても戻らないようにする。

### マス目で塗り絵にしない

1マスずつお手本の明るさを写すだけの塗り絵になると、絵全体で明暗の大きな形をつかむ練習にならない。次のように作って避ける。

- お手本はマス目にせず、元の画像のまま見せる。
- マス目は16×12（縦長の絵は12×16）と粗くする。
- 塗りつぶしと大きいブラシを用意し、大きい面から決める順番にする。
- マス目は全部「中（灰）」から始め、明るい面と暗い面だけを塗る。

経過時間は出すが、制限時間で打ち切りはしない。

### 答え合わせ

全体の一致率と、明・中・暗ごとの正解率（正解がその値のマスのうち、同じ値で塗ったマスの割合）を出す。暗いところを取りこぼしがち、のような癖が分かるようにするためである。ずれたマスに印を付け、お手本、自分の塗り、3値の正解を並べ、かかった時間も出す。

### 画面

背景は暗い灰色にする。朝の布団の中でまぶしくないようにするためで、白・灰・黒のどれとも見分けやすい明るさにする。色はロゴと答え合わせのボタンのいくら色だけにする。

- iPadの横向き: お手本とマス目を左右に並べ、下に3色、ブラシ、塗りつぶし、戻す、別の絵、答え合わせのボタンを置く。
- スマホの縦向き: お手本とマス目を上下に並べ、ボタンは下に置く。

お手本の下に、タイトル・作者・所蔵館を小さく出す。

### やらないこと

- 連続日数や過去の結果の記録
- 端末どうしの同期、アカウント
- サーバー、外部のAPIをアプリから呼ぶこと
- ブラシで自由に描くモード、マスを細かくする設定（慣れてから考える）

## 開発

ビルドの道具は使わない。HTML・CSS・JavaScript（ES modules）をそのまま置き、リポジトリのルートをGitHub Pagesで配信する。

```sh
# 手元で動かす
python3 -m http.server 8000

# 作品を取ってくる（Pillowが要る）
python3 scripts/fetch_artworks.py
```
