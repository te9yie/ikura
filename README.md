# ikura

名画を明・中・暗の3値のマス目で写して、明暗（バリュー）を見る目を鍛えるPWA。朝、布団の中でiPadかスマホを使い、1日数分で終わる練習にする。

毎日1枚、パブリックドメインの名画が出る。その横の16×12の粗いマス目（慣れたら24×18の細かいマス目）を、その絵から取った3色の灰色で塗って写し、答え合わせで、お手本を3値に分けた正解との一致率を見る。鍛えたいのは、明るさを見分けて大きな形にまとめる目で、バリュースタディと同じ練習になる。

## 使い方

GitHub Pagesで配信する。iPadではSafariで開いてホーム画面に追加し、全画面で使う。AndroidではChromeで開く。

## 仕様

### 作品は先に用意して、リポジトリから配る

作品はアプリから美術館のAPIを呼んで取らない。`scripts/` のスクリプトで、Art Institute of ChicagoとMetropolitan Museum of Artのパブリックドメインの絵画を数百枚取ってきて、`artworks/` に入れておく。サーバーを持たず、GitHub Pagesだけで動かすためである。Metropolitan Museumの画像はCORSのヘッダーを返さないので、ブラウザから直接読むとcanvasが汚染されてピクセルを読めない。

スクリプトは作品ごとに次のことをする。

- 絵画でないもの（版画・写真・工芸など）と、縦横比が4:3から離れすぎたものを外す。
- 4:3（横長）か3:4（縦長）に中央で切り抜き、長辺800pxのJPEGに縮める。
- 絵のパレットを、絵全体のピクセルの明るさ（CIE L\*）から作る。ピクセルのL\*を3つの塊にまとめ（1次元のk-means）、塊ごとの平均の明るさの灰色をパレットの暗・中・明にする。3値の正解は、粗いマス目（16×12）と細かいマス目（24×18）のそれぞれで、マスごとの平均のL\*に一番近いパレットの色にする。ちょうど真ん中のマスは暗いほうにする。マスの平均からパレットを作ると、細い白い布のような明部はマスの中で暗い色と混ざって平均が下がり、一番明るいマスにならない。一番明るいマス・一番暗いマスの2つで決めると、1マスだけ飛び抜けたマスにパレットが引っぱられる。マスの数で三等分すると、明るいマスが少ない絵でも3分の1が明になる。白・灰・黒の固定の3色に近い色で分けると、暗い絵の多くで明のマスが1つもなくなる（359枚のうち237枚）。
- 3値に分けても明暗の幅が狭いもの（ほぼ真っ黒な絵など）を外す。明暗の幅は、粗いマス目で明のマスの平均L\*から暗のマスの平均L\*を引いた値で、15より小さいものを外す。15は仮の値で、`.cache/review.html` で絵を見比べて決め直す。
- 候補をIDのハッシュの順に見て、採った順に `artworks/index.json` に書く。シャッフルしたのと同じく館や画家が混ざって並び、再実行で作品を足しても、既にある作品の順番は変わらない。

`artworks/index.json` には、作品ごとに画像のファイル名、タイトル、作者、所蔵館、元のページのURL、向き、3値の正解とパレットを持つ。正解はスクリプトで作っておくので、アプリでは画像のピクセルを読まない。

```json
{
  "version": 1,
  "artworks": [
    {
      "id": "met-436535",
      "image": "met-436535.jpg",
      "title": "Wheat Field with Cypresses",
      "artist": "Vincent van Gogh",
      "museum": "The Metropolitan Museum of Art",
      "url": "https://www.metmuseum.org/art/collection/search/436535",
      "orientation": "landscape",
      "cols": 16,
      "rows": 12,
      "answer": "222211110000…（192文字）",
      "palette": ["#141414", "#545454", "#9f9f9f"],
      "fine": {
        "cols": 24,
        "rows": 18,
        "answer": "222222111111…（432文字）",
        "palette": ["#141414", "#545454", "#9f9f9f"]
      }
    }
  ]
}
```

| フィールド | 中身 |
|---|---|
| `id` | `met-{objectID}` か `aic-{id}` |
| `image` | `artworks/` からの相対パス。アプリでは `artworks/` + `image` のパスで読む。画像は横長なら800×600、縦長なら600×800 |
| `title` | 作品名 |
| `artist` | 作者。分からなければ空文字で、空ならアプリでは出さない |
| `museum` | `"The Metropolitan Museum of Art"` か `"Art Institute of Chicago"` |
| `url` | 所蔵館の作品のページ |
| `orientation` | `"landscape"` か `"portrait"` |
| `cols`、`rows` | 横長は16と12、縦長は12と16 |
| `answer` | マスの3値を行優先（左上から右へ、次の行へ）に並べた `cols × rows` 文字。`"0"`＝暗、`"1"`＝中、`"2"`＝明 |
| `palette` | 絵のパレット。暗・中・明の順に、灰色を小文字の `"#rrggbb"` で3つ並べる。アプリはこの色で塗らせ、答え合わせを描く。ない作品では style.css の黒・灰・白を使う |
| `fine` | 細かいマス目の `cols`・`rows`・`answer`・`palette`。横長は24と18、縦長は18と24で、`answer` の形は粗いほうと同じ。`palette` は絵全体から作るので粗いほうと同じ値。アプリは `fine` がないか形が合わない作品では、細かいマス目を選んでいても粗いほうを出す |

並びは `artworks` の配列の順で、アプリではこの順で「今日の絵」と「別の絵」を選ぶ。

### 1日1枚、日付で進める

決まった基準日からの日数を作品の数で割った余りで、今日の1枚を選ぶ。一巡するまで同じ絵は出ず、iPadとAndroidで同じ日に同じ絵が出る。

基準日は2026-01-01で、決めたあとは変えない。変えると、その日から出る絵がずれる。日数は端末のローカル日付の年月日だけで数え、時刻の差からは出さない。時刻の差で数えると、夏時間の切り替わりの日は23時間か25時間なので1日ずれる。日付は開いたときと、画面がもう一度見えたときに確かめ、変わっていれば今日の絵に替える。作品の数が変わると、その日から出る絵も変わる。

練習に向かない絵が出たときは「別の絵」のボタンで並びの次の絵に替える。何度でも押せて、押すたびに次へ進み、末尾の次は先頭に戻る。替えたことはその日のうちだけ `localStorage` に残し、開き直しても戻らないようにする。

### マス目で塗り絵にしない

1マスずつお手本の明るさを写すだけの塗り絵になると、絵全体で明暗の大きな形をつかむ練習にならない。次のように作って避ける。

- お手本はマス目にせず、元の画像のまま見せる。
- マス目は16×12（縦長の絵は12×16）と粗くする。慣れたら「細かいマス」のボタンで24×18（縦長の絵は18×24）にできる。32×24まで細かくすると、スマホの縦向きで1マスが11pxほどになり、指で塗れない。
- 塗りつぶしと大きいブラシを用意し、大きい面から決める順番にする。ブラシは1マスと3×3の2つで、最初は3×3にしておく。
- マス目は全部「中」から始め、明るい面と暗い面だけを塗る。

細かいマスを選んだかは `localStorage` に残し、次の日も同じマス目で始める。切り替えると、同じ絵を全部「中」から塗り直し、経過時間も0から数え直す。塗ったあとに切り替えるときは確かめてから消す。粗いマス目の塗りは細かいマス目にそのまま移せないためである。

経過時間は出すが、制限時間で打ち切りはしない。お手本の画像が出たときから数え、画面が隠れている間（別のアプリに移った、画面を消した）は止める。布団の中で画面を消して置いた時間まで数えると、練習にかかった時間にならないためである。

### 答え合わせ

全体の一致率と、明・中・暗ごとの正解率（正解がその値のマスのうち、同じ値で塗ったマスの割合）を出す。暗いところを取りこぼしがち、のような癖が分かるようにするためである。ずれたマスに印を付け、お手本、自分の塗り、3値の正解を並べ、かかった時間も出す。

並べ方は2×2で、上の段にお手本と自分の塗り、下の段に数字と3値の正解を置く。自分の塗りは塗る画面のマス目と同じ右側に、正解はその真下に来るので、上下で見比べられる。iPadでもスマホでも同じ並べ方にし、お手本・自分の塗り・正解は同じ大きさにする。

ずれの印は、自分の塗りの上で、ずれたマスの真ん中に描く小さな四角である。一辺はマスの40%（小さくても4px）で、色は正解の値の色にする。自分の色と正解の色は必ず違うので、暗・中・明のどの組み合わせでも見え、「暗を中で塗った」のようにどちらへずれたかが印だけで分かる。色を足さないのは、色をロゴと答え合わせのボタンだけにしているためである。

経過時間は答え合わせのボタンを押したところで止まる。答え合わせのあとにできることは「塗りにもどる」だけで、押すと塗りを残したまま塗る画面に戻り、時間は止めた所から続く。もう一度答え合わせを押すと、そこでまた止まる。答え合わせを間違えて押したときに戻れるようにするためで、最初から塗り直したいときは開き直す。

### 画面

背景は暗い灰色にする。朝の布団の中でまぶしくないようにするためで、黒・灰・白のどれとも見分けやすい明るさにする。色はロゴと答え合わせのボタンのいくら色だけで、塗る3色は絵から取った灰色にする。

お手本とマス目は同じ大きさで出し、左右に並べるか上下に並べるかは、マスが大きくなるほうを画面の大きさと絵の向きから計算して選ぶ。iPadの横向きでは左右、スマホの縦向きでは上下になる。画面の向きで決めないのは、縦長の絵と横長の絵で収まり方が違うためである。上下のときは、お手本、タイトル、マス目の順に並ぶ。

お手本の下に、タイトル・作者・所蔵館を小さく出す。

ボタンは画面の下に置き、3色、ブラシ、塗りつぶし、戻す、経過時間、細かいマス、別の絵、答え合わせの順に並べる。幅が600pxより狭い画面と、1段に収まらない画面では2段にし、上の段に3色・ブラシ・塗りつぶし・戻す、下の段に経過時間・細かいマス・別の絵・答え合わせを置く。ボタンの高さは44px以上にする。

指で塗る間に、ページがスクロールしたり拡大したりしないようにする。ピンチ・ダブルタップでの拡大、iOSのバウンス、Androidの引っぱって更新、長押しでの文字選択や画像の保存メニューを止める。ノッチやホームバーのある端末では、画面の端の安全な範囲の内側に並べる。

### オフラインでは一度開いた絵だけが出る

ホーム画面に追加して、アプリとして全画面で開く。アイコンは暗い灰色の地にいくら色の粒を1つ置いた絵で、地をアプリの背景と同じ色にして、開いたときに色が切り替わらないようにしてある。

manifestのファイル名は `app.webmanifest` で、変えない。最初は `manifest.webmanifest` だったが、AndroidのChromeでインストールすると「このアプリはすでにインストールされています」と出て、開こうとしても「アプリを開けませんでした」になった。端末にもChromeにもikuraは入っておらず、Chromeのデータを全部消しても、manifestの `id` を変えても直らなかった。WebAPKのパッケージ名はmanifestのURLから作られるので、同じ名前のパッケージが端末のどこかに残っていると推測して、URLを変えた。

アプリのファイルと作品の一覧は先にキャッシュし、作品の画像は開いたものだけを残す。オフラインでは一度開いた絵だけが出る。初めて開いた日の今日の絵は、もう一度開いたときにキャッシュに入る。開いたことのない絵が今日の絵になったときは、お手本の場所に「画像を読めませんでした」が出る。

作品の一覧は起動のたびに取りに行く。3秒で返らなければ前に取った一覧を使う。古い一覧のままだと、作品を足した日にiPadとAndroidで別の絵が出るためである。

新しい版は、全部閉じて開いたときか、開いたまま日付が変わったときに替わる。塗っている途中や読み込みの途中で、古いファイルと新しいファイルが混ざらないようにするためである。日付が変わって画面が見えたときは、開き直して作品の一覧も読み直す。

### やらないこと

- 連続日数や過去の結果の記録
- 端末どうしの同期、アカウント
- サーバー、外部のAPIをアプリから呼ぶこと
- ブラシで自由に描くモード（慣れてから考える）
- 24×18より細かいマス目

## 開発

ビルドの道具は使わない。HTML・CSS・JavaScript（ES modules）をそのまま置き、リポジトリのルートをGitHub Pagesで配信する。

```sh
# 手元で動かす
python3 -m http.server 8000

# 作品を取ってくる（index.json が30枚になるまで足す）
uv run scripts/fetch_artworks.py
uv run scripts/fetch_artworks.py --count 300
uv run scripts/fetch_artworks.py --reanalyze  # 全部の作品の正解とパレットを作り直す

# アイコンを描き直す（icons/ に書き出す）
uv run scripts/make_icons.py

# スクリプトのテスト
uv run --with pillow python -m unittest discover -s scripts

# アプリのテスト
node --test "tests/*.test.js"
```

アプリのうち、日付から作品を選ぶような、画面に触らない計算は `lib/` に分け、`tests/` のテストをnodeの標準のテストランナーで動かす。npmもpackage.jsonも要らない。`node --test tests/` とディレクトリを渡すと失敗するので、上のようにファイルの形で渡す。

アプリのファイルを変えたら `node --test` が sw.js の VERSION に入れる値を出すので、それを入れる。VERSION はキャッシュするファイルの中身のハッシュで、入れ忘れると版が上がらず、古いファイルが出続ける。新しいファイルを足したら sw.js の PRECACHE に足す。index.html と style.css が読むファイルと、app.js・`lib/` の .js が相対で import するファイルは、足し忘れるとテストが落ちる。service worker は安全な文脈（HTTPSか localhost）でしか動かないので、LANのIPアドレスでhttpで開くと登録されない。

手元の localhost でも service worker が登録されるので、一度開いたあとは、app.js や style.css を直して再読み込みしてもキャッシュの古いファイルが出る。VERSION を入れ直しても、新しい版はタブを全部閉じるまで替わらない。直しながら見るときは、Chrome の開発者ツールの Application → Service workers で「Update on reload」か「Bypass for network」に印を付ける。scope は `http://localhost:8000/` になるので、あとで同じポートでほかのプロジェクトを配ると、ikura の index.html や app.js が返る。ikura の作業を終えたら同じ画面の「Unregister」で外すか、`python3 -m http.server 8001` のようにプロジェクトごとにポートを分ける。

アイコンのPNGは `scripts/make_icons.py` で描いて、書き出したものをコミットする。色は style.css の `:root` から読む。

作品のスクリプトはPythonで書き、依存はPillowだけにしてある。`uv run` で動かすと、スクリプトの先頭の宣言に従って、Pillowを入れた環境で動く。Pillowを入れたPythonがあれば `python3 scripts/fetch_artworks.py` でも動く。uvはこのスクリプトを動かすためだけに使い、ブラウザで動くコードには使わない。

キャッシュは `.cache/` に置く（コミットしない）。再実行では、キャッシュにある候補は落とし直さない。確認用のHTMLに載せる絵の3値化の結果も `.cache/analysis.json` に残し、画像が変わっていなければ計算し直さない。`.cache/review.html` をブラウザで開くと、3値まで計算した絵を明暗の幅の小さい順に、粗いマス目の3値の正解と並べて見られる。`index.json` に細かいマス目の正解かパレットがない作品があれば、再実行で `artworks/` の画像から粗いマス目と細かいマス目の正解とパレットを作り直す。正解の作り方を変えたときは `--reanalyze` を付けて再実行すると、全部の作品を作り直す。変な絵があったら `scripts/excluded.txt` にIDを書いて再実行すると、`index.json` から外れて次の候補で埋まる。明暗の幅の基準を変えて最初から作り直すときは、`artworks/` を消して `--min-spread` を付けて再実行する。
